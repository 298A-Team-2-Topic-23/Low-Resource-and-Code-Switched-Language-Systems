# Synthetic code-mixing: first batch

Linear **298-17**. Generated by `scripts/generate_codemix.py`; do not edit by hand.

## Status, stated precisely

**The pipeline is stood up. The arm is not validated.** What exists:

- IBM Model 1 alignment by EM, no external aligner and no network
- Equivalence-Constraint block segmentation over the alignment
- generation of every EC-licensed mixed realisation per sentence
- selection matched to a target switch-point fraction rather than uniform
- 28 tests

What does not exist: a run on a real parallel corpus, and any model trained on
the output. Model 4 is 298B work and this is its input stage, not its result.

## Reading the numbers honestly

**17 of 30 sentences produced only one block**, so they could not be mixed at
all. That is a corpus-size artifact: Model 1 needs far more than 30 sentences to
learn alignments sharp enough to produce crossing links, and without crossings
there is no licensed switch point. On Samanantar this should fall sharply, and
if it does not, that is a finding worth reporting.

**Pool utilisation decides whether the target is reachable.** Matching can only
steer what it can leave behind. At `--per-sentence 2` this batch consumed 76% of
the pool and the mean SPF rose to 0.29, outside tolerance — not because matching
failed but because there was nothing left to choose. The statistics report
`pool_utilisation` and `pool_exhausted` so this is visible rather than
mysterious.

**Some outputs are poor.** `mujhe Please` is a legitimate EC realisation of a
two-block sentence and also not something anyone would write. Short sentences
with many-to-one alignments produce these. A length floor would hide them; they
are left in because the failure mode belongs in the failure analysis.

## Running it on real data

```
python3 scripts/generate_codemix.py --input data/raw/samanantar.roman.tsv \
    --target-spf 0.2398 --per-sentence 3 --seed 42
```

Two prerequisites, neither met today:

1. **A licensed parallel corpus.** Samanantar and IIT Bombay are licence-checked
   in `docs/datasheet.md`; neither is in the repository.
2. **Romanised Hindi on both sides.** The generator refuses Devanagari rather
   than emitting mixed script, because the task output is Romanised Hinglish.
   Lifting that needs Dakshina, which the datasheet lists and we do not have.

Until both land, this batch is evidence that the pipeline runs, and nothing more.
