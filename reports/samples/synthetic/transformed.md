> **Synthetic corpus.** These samples prove the emitter runs; they are not a reportable sample set. Regenerate against `data/raw/hinge.csv` before any report section quotes them.

Every transformation the pipeline applies, each with the reason it exists. Normalisation here is structural only -- spelling is never normalised in the corpus, because orthographic variance is the phenomenon under study. The metric applies its own normalisation separately, in `evaluation/run_eval.py`.

## Transformations and why

| transformation | applied to | reason |
|---|---|---|
| Unicode NFC and whitespace collapse | every field, at ingest | one code point sequence per grapheme, so two spellings differ only when they really differ; applied once so later stages cannot disagree |
| reference-list expansion | the Hinglish cell, at ingest | HinGE ships multiple human references per source sentence in a single list-literal cell; one record per reference is what supervision needs |
| record id | derived from (english, hinglish) | content-addressed, so a record is citable across runs and machines without redistributing the text |
| near-duplicate group id | derived at the split stage | the lexicographically smallest key in the cluster, so the id depends on content alone and not on iteration order |
| split TSV layout | id, group, english, hindi, hinglish | the five columns the model scripts read; hindi is carried so the baseline reproduction can run its original two-input condition |

## Whitespace and NFC normalisation, before and after

Normalisation is applied inside stage 1, so by the time a record exists it is already normalised and no before/after pair survives to be shown here. The transformation is evidenced by `tests/` instead; see `lrcs.text.normalise`.
